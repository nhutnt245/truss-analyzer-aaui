# Path 3: convert an existing app

For an app or page built with something else (another component library, utility classes, hand-written CSS) that must look and behave like AtomicAUI.
**This version: React pages, moved one by one into an app made from this kit.** An app or page that is not React and keeps its own stack (plain HTML, Razor, Blazor, MVC, another framework), to follow AtomicAUI where it is, the whole app, some pages or one element: that is `../aui-style-anything/references/restyle.md`. Go there and do it; it is the path for the job, not something to offer, and it needs no one to agree. Only to move such a page into a new app instead: inventory and photograph it in step 1, record it as not moved in step 5, skip the React map and the remaining steps, then stop and say so ("Not in this version").
The person picks where React pages go: a new app made from this kit (this page), or inside the old React app. Inside the old React app is not written yet: say "Converting inside the old app is not in this kit version", offer the new app, and go on only when they agree.
People: the same five steps with prompts to paste, or by hand, are in `references/convert/start.md`. An assistant does not need that page.

## When a session ends
Asked to convert a page, the session ends when that page is built in `src/screens/`, opens at its address, and step 5 is written. A request that asks for less ends when what it asked for is done: the assessment alone ("assess", "show me the map", step 1 by name), or another step by name ("Step 3 of `references/paths/convert.md`", as the prompts in `references/convert/prompts.md` ask). A gap never ends a session: a control with no part, or a part that does less than the old one, takes the nearest choice the kit names, in the old control's place, with a `GAPS.md` line, `// OPEN:` and a line in your final message, and the page is built. A page built with a recorded gap is moved; say "moved, with gaps", never "same as the old page". The only stops are the ones this page names: no old app to pick (step 1, item 1), a page that is not React, converting inside the old app (not written), and a "no part" control that a person recorded in `CONVERSION.md` as waiting for the kit (step 3, item 6). Then say which.

## Order of the checks
No full `npm run verify` before the page exists: it takes about 5 minutes on a fast machine (longer on a busy one) and measures nothing of your page. Once, before any page moves: `npm run verify:fast` (a few minutes, no browser tests), in the foreground: wait for its last line and never end your turn while it runs. Then build the page, run `npm run verify:page -- <Page>` while you fix, write your final message and the checklist, and run `npm run verify` once, last.

## What never changes
- All built logic stays as it is: handlers, state, data calls, addresses, validation rules, texts. The old page's behaviour is kept, except where an AtomicAUI part adds standard behaviour the old page lacked, such as Escape closing a dialog; list each difference in `CONVERSION.md`. An odd text or a typo is kept and listed, never fixed.
- Same regions and words as the old page. Where the old order differs from the AtomicAUI pane, the pane's order wins: its title comes before body content, including a breadcrumb. Record that provisional choice. Nothing added, nothing lost (AUI-07).
- The kit decides the look: spacing, sizes, colours, which button is the main action, and the order of button and filter rows (Cancel or Reset first, the main action last); record the order change in `CONVERSION.md`. Old spacing, colours and class names are never carried over (AUI-05).
- Light and dark always. A phone layout only when asked.
- One page per session. A page is not started before the page before it is proved.
- The old app is only read. Never edit it; it keeps running until its last page has moved.

## The five steps
| Step | You make | Done when |
|---|---|---|
| 1 Assess | `CONVERSION.md`: the pages, the pictures of each as it is, what each must still do, the map | the map is in `CONVERSION.md` (a person reads it first only when the request was for the assessment alone) |
| 2 Load AtomicAUI | the new app, made from this kit | `npm run verify:fast` passes before any page moves, and the set-up is in one commit |
| 3 Convert one page | `src/screens/<Page>/` | `npm run check` passes |
| 4 Prove that page | pictures, behaviour, a filled checklist | the page-only run passes and you looked |
| 5 Record | `CONVERSION.md` says what moved and what remains, with your final message and the filled checklist | the last full `npm run verify` passes and its last lines are in the checklist, then the page and the record are in one commit |

Steps 1 and 2 are done once per app; steps 3 to 5 repeat for each page. Stopping after any step 5 is fine: the next session starts by reading `CONVERSION.md`, and the next page starts at step 3.

## Step 1: assess (once per app; the old app is read-only)
1. **Before you ask anything, read `specs/` and look in `../` for the old app** (the spec often names it). Say "Path 3: convert", the old app's name or repository, its folder relative to this one (for example `../old-app`) and its address when it runs. Ask only for what is still missing, and only when the request was for the assessment alone. **Asked to convert** (a one-shot task, where the prompt gives the whole job and no one is there to answer, is one): write each unknown as a line in `GAPS.md` (and a provisional pick in `CONVERSION.md`), name each provisional pick in that first message (for example which folder in `../` you took as the old app) so that a person who is there can correct it at once, and go on; do not stop to ask. Nothing to pick from (`specs/`, the request and `../` name or hold no old app): that is a stop; say what is missing and where you looked. Use relative filesystem paths in `CONVERSION.md` and `conversion/`. The record and view definitions are committed; old-page pictures and measurements in `conversion/before/` and sibling `conversion/before-*/` folders are private and ignored by git. Keep page addresses as they are, even when a URL path starts with `/home/`. The private-content rule of `npm run check` (KIT-02) reads neither location.
2. Copy `references/convert/tracker.md` to `CONVERSION.md` only if `CONVERSION.md` does not exist. A record that exists is read and added to, never copied over. List every page of the old app and the states of each (empty, filled, an open dialog, an error).
3. Pictures of the old pages: use test or sample data, never live user records. If the new app is nested in the old repository and the old dev server picks up its second React copy from nested `node_modules`, build the old app and use its preview for baseline pictures. Write `conversion/before.views.json` (every page and state in this one file, one view each, the form of `evidence.views.json`), start the old app, then
   `node scripts/evidence.mjs --url <old app address> --views conversion/before.views.json --out conversion/before`. It works on any stack. `click` finds exact text on a button, link, tab, tree item or table cell, or an exact `aria-label` or `title`. A missed click still writes a picture: open `conversion/before/measure.json` and require empty `missedClicks` for every entry, then open every picture to confirm its page and state. Check each separate output folder's `measure.json` too.
   A view's `url` holds only what follows `?` or `#` in the address. A page with its own path (`/orders`): reach it with `click` on its link from the first page. No link leads to it: its own views file and run, with the path in `--url` and its own sibling `--out` folder (`--url <old app address>orders/ --views conversion/before-orders.views.json --out conversion/before-orders`), because a run empties its `--out` folder. Keep separate capture folders beside `conversion/before/` with names beginning `before-` so they are ignored too. Record each page's capture folder in its `CONVERSION.md` row: `conversion/before/` for the primary run, or the sibling folder used for its separate run.
4. Under "Behaviour to keep" write, per page, what each control does, in the old page's own words: what Enter does, what is disabled until when, what a dialog asks. Read the code for it; do not guess (AUI-08). Note any AtomicAUI standard behaviour the old page lacks under "AtomicAUI behaviour differences" in `CONVERSION.md`. Name old tests that find things by role and name; preserve them for unchanged behaviour.
5. The map: one row per kind of thing the old page uses (element, class, value), from `references/convert/map-react.md`: what it becomes, what is dropped, what to watch. A thing with no row: the stop rule of `references/rules.md`, steps 1 to 4. None fits: write "no part" and what it does. List every "no part" control under "Gaps and open questions", with one line each in `GAPS.md`: this list is what can be built into the kit first.
6. Show the map and the list of "no part" controls in `CONVERSION.md`. Each "no part" control gets one answer, in this order: the stop rule builds it (`references/rules.md`, steps 1 to 4; say what fits, if anything); else the part is built into the kit first and the page uses it; otherwise the page improvises it, as long as it follows the AtomicAUI standard (step 3, item 6). Asked for the assessment alone: stop here, and a person answers each. Asked to convert: answer each yourself with the first or the last of that order (only a person can say a part is built into the kit first: AUI-13), mark each pick provisional, say it with the map, and go on. Write each answer in `CONVERSION.md`.

## Step 2: load AtomicAUI
1. The new app is a copy of this kit's starter: `npm install`, then `npm run verify:fast` in the foreground, waiting for its last line (not in the background, and never ending your turn while it runs), and it must pass (not the full verify: it comes last, in step 5), set the app's name in `src/app/app.config.ts` (the name the request gives, else the old app's name, recorded as provisional). This is done once per app.
2. Copy the old app's own logic files (data calls, helpers) unchanged into `src/data/legacy/`, which holds `.js` and `.ts` logic only. Lint, KIT-02 and the AtomicAUI screen rules skip these files; typecheck counts errors inside them as ignored. Errors in app-owned adapters elsewhere in `src/data/` and in screens that import the logic still fail. Do not put `.jsx` or `.tsx` there: any UI moves into a screen under `src/screens/`, where the checks apply. Prove the copied logic's behaviour with the page's behaviour test (step 4). Put any needed declarations beside a JavaScript file in `<name>.d.ts`. A JavaScript screen that holds JSX becomes `.tsx` under `src/screens/`.
   Put screen fixture data in `.ts` files under `src/data/fixtures/`, so source IDs such as IFC `#101` are not mistaken for a screen colour. Only that folder, and only `.ts` files, is left out of the colour check: a styling colour anywhere else in `src/data/` is still reported.
3. A library the copied logic needs (routing, fetching, dates): `npm install` it, and leave the copied import unchanged. The old UI library and the old stylesheets are never installed or copied.
4. The frame first: the app name and the menus of the top bar (`references/recipes/app-frame.md`). The old header, footer and side navigation are not copied.
   Keep every top-bar link of the old app; a link to a page not moved yet points at the old app's address.
5. Commit the set-up before the first page: the record, the view definitions, the name, the frame and the copied logic. Capture folders stay local. Only the app's owner may opt in to committing captures made with test or sample data, using `git add -f conversion/before` and the same command with each existing sibling folder's exact name. An undo on the first page returns to this commit, and the page starts again at step 3.

## Step 3: convert one page
1. `src/screens/<Page>/<Page>.tsx`; a line in `src/screens/index.ts`; its address in `src/app/route.ts` and `src/app/Screen.tsx`; its views, with the clicks that show each state, in `evidence.views.json`. When the new default address changes, update the app-owned expectations in `src/app/App.test.tsx` and `src/app/route.test.ts` to that address and page.
2. Copy the old component's logic lines as they are: state, handlers, effects, data calls. Rewrite only what it returns, element by element, by the map. A screen that was JavaScript is now `.tsx`: add the types the type check asks for on the copied lines (a parameter's type, a state's type, a `!` after a value the old code trusts to be there) and change nothing else in the line; a type adds no behaviour. A logic file or library this page needs that the new app does not have yet: step 2, items 2 and 3.
3. The page is `Panes`, `Pane`, `PaneBody` (`references/components/panes.md`). The old page title becomes the pane title. If a breadcrumb preceded it, put the breadcrumb first in `PaneBody`: the pane title must come first. Buttons that sat beside the old title go in a toolbar bar at the top of the body, never in the pane header. Every bar of one card takes the same constant and colour (`{ ...BAR_AUI, color: 'surface-alt' }`), a table spreads `TABLE_PROPS`, space comes from `references/spacing.md`.
4. A look that a class switched (`active`, `selected`) becomes the part's own state: `selected` on a `Table.Row`, `disabled` on a `Button` (AUI-04).
5. Work the "watch" column of each map row. These went wrong in the kit's own trial:

| Old | Watch |
|---|---|
| `<form onSubmit>` | Keep it: `<View as="form" onSubmit={...}>`. Enter must still submit |
| A select whose value is not its label | `items={[{ value, label }]}` on `Field.Select`, or it shows the raw value |
| A link in a bar or a breadcrumb | `<Button role="link" aui={NAV_LINK_AUI} nativeButton={false} render={<a href="..." />}>`: no underline (`check:layout` fails one in a bar, breadcrumb, tab list or menu) |
| A link that is a tab | `Tabs.Tab` with `nativeButton={false} render={<a href="..." />}` and `aui={{ sx: { textDecoration: 'none' } }}`: no underline, and it keeps its chip (never `NAV_LINK_AUI`, `references/components/tabs.md`) |
| A link in a menu | `<Menubar.DropdownLinkItem aui={NAV_LINK_AUI} href="...">`: no underline (`references/recipes/app-frame.md`) |
| A link inside running text | `<Button role="link" aui={{ paint: 'text' }} nativeButton={false} render={<a href="..." />}>`: it keeps its underline |
| A dialog | A sibling of `<Panes>`, never a child: a child becomes a pane. A destructive confirm is `AlertDialog`; Escape closes it even if the old dialog stayed open. Record the difference |
| A label beside its control | `aui={FIELD_AUI}` on the `Field`: the label goes above the control (`FIELD_DIALOG_AUI` in a dialog). It must stay beside: `FIELD_INLINE_AUI` with its row (`references/components/field.md`, "Layout"). A row or a gap written on the `Field` fails `npm run check` (AUI-09) |
| A wide table | `minInlineSize={720}` on `Table`, so a narrow window scrolls the table, not the page |
| A mark the old CSS drew (`content: '/ '`, a bullet, an asterisk) | It is a word of the page: write it as text in the same place |

6. A "no part" row: do what `CONVERSION.md` records for it (step 1, item 6). Built by the stop rule or improvised, it follows the AtomicAUI standard: only AtomicAUI parts, `View` and `Type`, the thirteen rules hold and `npm run verify` passes, with no `check-allow` and none of the old control's CSS. It waits for the kit only when a person said so in `CONVERSION.md`; then the page stays in the old app and the record says what it waits for.
7. `npm run check`. Fix what it names. Never add `check-allow` to pass, except the import of step 2.

## Step 4: prove the page
1. **The page-only run, as often as you need while you fix.** The full `npm run verify` takes about 5 minutes on a fast machine, longer on a busy one (its browser tests run one file at a time), so do not use it to debug. With `<Page>` your folder name under `src/screens/`:
   ```
   npm run verify:page -- <Page>
   ```
   It runs, one at a time, and stops at the first that fails: the rule check, lint of the page, its routing and `src/data`, the type check, the page's own tests, the layout check of every view in `evidence.views.json` and the evidence sheets of your styled pieces (`../aui-style-anything/references/proof.md`; no styled piece: it passes), in a few minutes. It prints a line before each step. It says nothing about the rest of the app: the full run in step 5 does. A check that says SKIPPED measured nothing: say so.
2. Open the four pictures of each view of this page in `evidence/` beside the old ones in this page's capture folder recorded in `CONVERSION.md` (`conversion/before/` or its `conversion/before-<page>/` sibling). Same regions and words; account for the pane order in step 3. Every label can be read in full. A select shows its label. Nothing overlaps or is cut off, light and dark, 1440 and 390 wide. Name every picture you opened in your report; a picture you did not open was not looked at.
3. Behaviour: every line for this page under "Behaviour to keep" is tried in the running app, or covered by a test that finds things by role and name. Check each recorded AtomicAUI behaviour difference for this page too. Old tests for this page's unchanged behaviour pass unedited; update a test only when it conflicts with a recorded standard behaviour. A line for this page you did not try: say so.
4. Fill a copy of `references/checklist.md`. Its `npm run verify` line waits for step 5.

## Step 5: record
In `CONVERSION.md`: the page's row (moved, proved, date), every gap, every "no part" control and what was decided, every kept oddity, each AtomicAUI behaviour difference, every open question, and what is not done. Add missing parts to `GAPS.md`.
**Checks before claims.** Paste the result lines of the page-only run (step 4) before you claim anything; a check you did not run is "not run", never "passed". Write your final message and the checklist before the last full run (`npm run verify` where the app has it), its line saying "verify not finished", then put its last line in both when it ends. Wait for that last line: never end a turn, and send no message, while a command you started still runs.
**Do it now** (a copy of `references/checklist.md` as `CHECKLIST.md`, its `npm run verify` line left unticked as "not finished"; the message under the page's row in `CONVERSION.md`: the six lines of "My final message" in `references/checklist.md`, its "Checks run" line saying `npm run verify: not finished`). Then run `npm run verify` once, last, in the foreground (a tool that ends a command before it finishes: in the background, reading `verify.log` again and again, waiting between reads, and never ending your turn while it runs); its last line, in `verify.log` too, says `verify: ok`, `verify: FAILED at step N`, `verify: TIMED OUT at step N` or `verify: STOPPED at step N` (the last two did not finish: read what it printed above, run it again, and say "not finished"); send no message and do not end your turn while it runs. When it ends, before the commit, put its last lines into that checklist line (ticked only if every step passed) and its last line into the message's "Checks run" line (`npm run verify: run, <its last line>`); a failed step also goes into "Not checked". If it fails, fix what it names with the command its last line gives (the page-only run, or the failed step alone), run `npm run verify` again, and correct the message, the checklist line and the page's row before the commit: a failed run is never written as passed, nor the page as proved. A full verify that is still running when your time ends must not leave you without a message: the message and the checklist already say "full `npm run verify` not finished".
Commit the page and `CONVERSION.md` together. Say what remains. Do not start the next page in the same session.

## Never
- Edit the old app, a kit file, or `src/vendor/atomic-aui` (AUI-06, AUI-13).
- Change a handler, a data call, a validation rule or a text "while you are there".
- Copy old CSS, old class names or old spacing into the new app.
- Add a helper line, a counter, an icon or a tooltip the old page does not have (AUI-07).
- Move two pages at once, or leave a page half moved (a region or control of the old page left out, recorded or not; a part that does less, in its place with its gap recorded, is not that).
- Say "done" without a green full `npm run verify` and the pictures (AUI-12). A full run that did not finish is not done: say so plainly.

## Not in this version
- Converting inside the old app, old and new on one page. Not written yet, also for a person who prefers it: the rule check reads only an app made from this kit, and panes fill the window.
- Moving pages that are not React (plain HTML, .NET) into a new app: inventory and photograph them (step 1), record them as not moved (step 5), and commit the record without a converted page; the rest is not written. Say: "Moving pages without React into a new app is not in this kit version. Restyling them where they are is: `../aui-style-anything/references/restyle.md`."
- A machine comparison of texts and controls before and after, an inventory script, and a count of what is left in the old app.
- A control with no part that must stay as it is on a converted page.
