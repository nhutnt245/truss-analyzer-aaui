# Overview page

Cards on the pane colour that sum up one thing: facts, a small table, messages, a status, a framed stat, a row of two blocks, a chart with supplied values, a drawing. Release 7.0.9. Code: `src/recipes/overview/` (`OverviewPage.tsx`, `sample.ts`). Running: `#/recipe/overview`; stat and row demo: `#/recipe/overview-layout`. These addresses work in the general starter only: the Aras pack's router does not know `recipe`, so with the pack on `#/recipe/overview` opens a search page (`GAPS.md`).
Make it yours: `npm run screen:copy -- overview`, then import it from `'@/screens'` instead of `'@/recipes/overview'`. **The copy, `src/screens/overview/OverviewPage.tsx`, is the file to edit**: change its `cards` and their blocks (and its sample data) into the spec's page; do not write a second page file beside it, and delete a copy you do not use. Without React: `references/standard/pages/overview.html`.
The copied test is yours: change its cases with the screen, delete a case your spec does not have, and run it alone with `npm run test -- src/screens/overview`.

## What it is
One pane (`Pane size="main"`) whose body has no shared card (`PaneBody surface="cards"`); in it a `CardGrid` of `SectionCard`s. The grid takes at most one column below 920 wide, two from 920, three from 1376 (86 rem), with 6 px between the cards both ways. The number of columns follows the number of cards, so the rows are even (hs `layoutSettings.ts:77-81`): rows = cards / most columns, rounded up; columns = cards / rows, rounded up. Above 1376: one card is one column, two are two, four are two and two, five are three and two. Nine apps go to three columns above 86 rem (hs `InputColumns.tsx:28-33`, rws `InputColumns.tsx:29`); 920 is the kit's own number (at 520 two columns made cards of 240 px, and the sample table wrapped its numbers), and so is the one column on a narrow page (AUI-10).
Our apps have this and nothing bigger: section cards on the pane colour, up to three columns, 6 px apart (rws `InputColumns.tsx:29`, hs, hcs `InputColumns.tsx:105`, adm, pbs, pfd `Pane.tsx:150-156`, agpd, fd, ace); facts as one text line each, `Label: value` (the released ADCCP `CalculationSummary.tsx:968-982`, the ADC prototype `Workspace.tsx:1738-1760`; the 160 px column of nine About dialogs is a chip column, not a label column); message banners (six); status chips (nine); a frame around a drawing (rws `Viewer.tsx:500-524`, adm, hcs, pbs, agpd).

## Props
`title`, and `cards: { id, title, blocks }[]`. A block is one of:
| `kind` | Shows |
|---|---|
| `facts` | `rows: { label, value }[]`, `label?` (the name a screen reader hears; default the card's title, so it adds no text of its own): one text line per fact, `Label: value`, in a column with no gap written |
| `table` | `label`, `columns`, `rows`: a small `Table` with `TABLE_PROPS` (`a11y="table"`) |
| `message` | `tone` (`success`, `warning`, `error`) and `text`: a solid banner; an error is `role="alert"` |
| `status` | `label` and `tone` (`info`, `success`, `warning`, `error`, `surface-alt`): a solid `Chip` at size `sm` |
| `stat` | `icon`, `label`, `value`: a framed `Card` with an `Icon` and one `Label: value` fact line. Use a source-provided icon name and value; the card adds no summary of its own |
| `row` | `label` (accessible name) and exactly two `blocks`: the first and second blocks sit beside each other when the row is at least 920 wide, and stack in that order below 920; use it for a table beside a chart without squeezing either at narrow width |
| `chart` | `type` (`bar`, `line`, `area`, `pie` or `radar`: the kind the spec or source draws), `label` (accessible name), `data` (rows with source numeric values), `categoryKey`, `series: { dataKey, label }[]`, and for `bar` and `area` an optional `layout: 'stack'`: AtomicAUI `BarChart`, `LineChart`, `AreaChart`, `PieChart` or `RadarChart`. Bar, line, area and radar draw one value per row and series, with category and value axes, grid and tooltip. Each series reads its own value on the value axis: bars side by side, areas each from the baseline; `layout: 'stack'` stacks them, only when the spec or source stacks. A pie draws one slice per row, named by `categoryKey`, with a tooltip. One series (one slice of a pie) is drawn in `primary` with no legend. Several are drawn in the library's default chart palette, six colours in its order, never one twice, so a chart with more than six series (or a pie with more than six slices) is drawn as the labelled placeholder. The palette colours are not theme role values; the token check accepts them on the marks of a chart series only (`references/token-check.md`). The default gradient of an area chart is no theme role either, so its fill is `solid` here. Several series use the library's clickable legend, whose buttons hide or show series or slices; the legend is always shown, with the tooltip, and never removed in the copy. The legend names each series but is itself a colour key, and the palette's colours differ by hue, not by lightness: for a reader who cannot tell the hues apart, in a still picture or on touch, series can be told apart only by the hover tooltip or by hiding a series through the legend (`GAPS.md`). Its swatches are circles and the chart's line height is 16, so that the legend passes the token check (`GAPS.md`). |
| `drawing` | `label`: a framed placeholder of at least 128 high, `role="img"`, the label in muted text |

## Rules
- **Start with `npm run screen:copy -- overview`** and edit the copy: use its `chart` block, with the `type` the spec or source draws, when the spec or source supplies the numbers, and never redraw one kind as another; for a kind the block does not have, a chart with more than six series or slices, or without numbers, keep a labelled `drawing` block, add `// OPEN:` and a line in `GAPS.md`. A variant the `chart` block does not carry (100% stacked, horizontal bars, a donut, and the like) is never drawn as the plain kind: it stays a labelled `drawing` placeholder, `// OPEN:`, and a line in `GAPS.md` that names the variant. Do not invent data or rebuild the page by hand.
- **The page title is the pane's `title`** (`<Pane title="Order summary">`, an `h2`), inside the pane frame: the spec's title and the pane title are one heading, never a second heading or a padded `View` above `Panes` (AUI-05, PN1: the page frame already holds the 8 px at the sides and 4 px above and below, so a padded wrapper around `Panes` fails the layout check: measured 16 px from the window). A subtitle has no slot in `Pane` (its header holds the title and `actions`): put it in the pane body, in one `View aui={STACK_AUI}` with the `CardGrid` (`<PaneBody surface="cards"><View aui={STACK_AUI}><Type as="p" role="p3" aui={TEXT_AUI}>…</Type><CardGrid label="…">…</CardGrid></View></PaneBody>`; a bare `Type` beside the grid touches it and fails AUI-05). That is a plain box and a text line (the stop rule's step 3), not a gap.
- **Two or more sibling sections that fold are an `Accordion`** (`Sections` from `@/recipes/layout`, `references/components/panes.md`), never several `Collapsible`s side by side (`references/components/collapsible.md`); a `Collapsible` is one block that folds on its own.
- A card the spec calls a stat card or an info card uses the `stat` block's framed `Card` (`references/chooser.md`), with its source icon, label and value on one fact line; a `SectionCard` is a titled section that holds blocks. A table beside a chart uses `row` with two blocks, so they stack in source order below 920. Facts stay one text line each, with no big-number tile.
- A status chip takes the tone the spec or source names; otherwise its usage context sets `success` for done, `warning` for in progress, `error` for failed, or `info` for informational; when the context is unclear, use the library Chip default `surface-alt` (`src/vendor/atomic-aui/lib/chip/use-recipe.ts:59`).
- A block that folds open and shut is `Collapsible` (`references/components/collapsible.md`; `aui={{ paint: 'text' }}` inside a card), never `useState(false)` and a `Button` with `aria-expanded`: `npm run check` fails it (AUI-01). A short list of lines is `List`, shown open, and a card with more than a few facts is a read-only form section (below).
- Cards to pick (a region, a size) are the copied styled piece `selection-cards`, with its line in `GAPS.md` (a card of a title and text: `description` on its option, the second group of the example page): `npm run check` fails a hand-built `<View selected>` (AUI-09). Never `CardGroup`. **Where it goes:** inside a card, as a block of a `SectionCard` or in the body card of a pane (`PaneBody`, the default `surface="card"`). Never as the direct children of `PaneBody surface="cards"`: the layout check then measures each picker card as a card of the pane (radius 4, 6 px apart) and the piece's 4 px gap fails AUI-09 ("cards are 4 px apart (must be 6)"). **Its evidence line** clicks a card by the start of its text: `{ "name": "member-pick", "url": "#/<your route>", "click": ["Standard member"] }` (a card's text is its title and its description joined; the name may stop after the title while only one card begins with it, and `npm run check:layout` says "nothing to click" when none or two do).
- No big-number tile: no app of ours has one. Use the `chart` block only for numeric values supplied by the spec or source. The gallery charts reuse the sample bill-of-materials quantities (bar at `#/recipe/overview`, pie at `#/recipe/overview-pie`) and the sample's monthly ordered and shipped quantities (`#/recipe/overview-line`, `-area`, `-radar`); they use AtomicAUI chart parts and the kit's theme-role series colours, not a look copied from an app.
- The cards, their order and their texts come from the source screen (AUI-07). The page adds no summary line of its own.
- The colour of a message or status follows the meaning, and the text says it: the colour never says it alone.
- `message` uses AtomicAUI `Banner` through the shared `MessageBanner` wrapper (`references/components/banner.md`). List a view that shows it in `evidence.views.json`. `facts` is plain `Type` lines.
- Fact lines are for short lists. A card with more than a few facts uses a read-only form section, which the kit already has: `FormFields` with `readOnly` (`src/recipes/form/FormPage.tsx`). The styled label-and-value piece (`label-value-rows`) stays for an app whose source screen has a label column (`GAPS.md`).
- Cards are cards: a line between two cards is a gap of 6 px, never an element.

## Without React
The page has no script to count its width, so the grid takes `aui-grid-template-columns-auto-fit`: as many columns of at least 320 px as fit. Change that class to `-2` or `-3` if you want a fixed count.
There is no class-form chart recipe. Keep and align an existing third-party chart on a restyled page; a new chart remains a labelled placeholder with a `GAPS.md` line (`references/paths/build-standard.md`).

## Mistakes
| Mistake | Fix |
|---|---|
| One white card around all of them | `surface="cards"`: each card is its own box on the pane colour |
| A heading inside a card written as a bold line | `SectionCard` writes the `h3`; the card is a group named by it |
| A number set big in a tile | Not in our apps: show it as a fact line |
| A chart drawn with SVG or boxes by hand | With supplied values, the `chart` block of the kind the source draws; without them, for a kind the block does not have, for more than six series or slices, or for a variant the block does not carry (100% stacked, horizontal bars, a donut), a labelled `drawing` placeholder, `// OPEN:`, and a line in `GAPS.md` |
