# The token check: any page, any stack

It proves a running page uses only AtomicAUI's theme values, in light and dark. No agent is needed: each problem says what to change. The page has the brand and theme attributes on `<html>` (copy them from `references/standard/page.html`) and loads the AtomicAUI stylesheet.
```
node scripts/check-conformance.mjs --url http://127.0.0.1:8080/page.html   # a local address: that one page
node scripts/check-conformance.mjs --url http://127.0.0.1:8080/ --views file.json   # many pages: only the file --views names
node scripts/check-conformance.mjs --url http://127.0.0.1:8080/page.html --tokens-only   # the token answer alone
```
The file of views names each page by a hash, a query or a path of that address, never another address:
```
[{ "name": "parts", "url": "parts.html" }, { "name": "order", "url": "/orders/7?tab=2" }, { "name": "home", "url": "#/home" }]
```
Every page is listed once as it opens: a view without steps. Content that appears only after a click or a typed word (the table a search draws, an opened item, a filter box, a dialog) is one more view of the same page, with `click`, the list of its steps, worked in order before anything is read. A view with steps is read only after them, so it never stands in for the page as it opens:
```
[{ "name": "search", "url": "search.html" },
 { "name": "results", "url": "search.html", "click": [{ "fill": "Product", "with": "pump" }, "Search", { "text": "Filters", "only": "desktop" }] }]
```
- **A name to click** (a string, or `{ "text": "<name>" }`): the `aria-label`, `title` or whole text of a button, link, tab, tree item or cell; the `value` of an `<input type="button">` or `submit`; or the whole text of any element with an `onclick` attribute. Of several elements with the same whole text, one inside the other, the innermost is pressed. A card is named by its title while only one control begins with it.
- **`{ "fill": "<box>", "with": "<text>" }`** types the text into a text box or text area that is on screen, enabled and not read-only: the box is named by its `aria-label` or the text of its `<label>` (with or without the colon at its end), then by its `id` or `name`, the first of these that matches. The events a script listens for fire (`input`, `keyup`, `change`).
- **`{ "scroll": "<name>", "only": "narrow" }`** brings a named element into the narrow viewport before the picture and measurement; name it by its exact `aria-label`, `title` or text. Use a separate view for each scrolled pane of a stacked page.
- **`"only": "desktop"` or `"narrow"`** on a step leaves it out at the other width.
- What a step sets going is waited for, before the next step and before the page is read: an answer it asks for in the background (a search that fetches its result and draws it), until the requests it started have ended, and a page it loads again (a submit in a form, a link), which is read in the theme of the run. A background answer is waited for 5 seconds at most: a slower one is read before it is drawn, with no failure, so open the picture of that view and see that the result is on it.
- A step that matches nothing is a failure of the view ("nothing to click or type in was found with the name ..."), never a pass: what the steps show was not read.
- **What a step cannot press yet**: an element that is none of the above and whose handler a script binds (`addEventListener`, jQuery `.on('click')` on a `<li>`, `<div>` or `<span>` without `aria-label`), and an image named only by its `alt`. On an old page you restyle, keep the page's view as it opens, leave out the view of that state, and list the state in `GAPS.md` and in your final message as not inventoried (`../aui-style-anything/references/restyle.md` step 2); never drop the page.
`check-conformance`, `check-layout`, `evidence`, `restyle-inventory`, `restyle-compare` and `restyle-done` work the same steps. `check-standard` takes the file with `--views file.json` and one `--url` (the address the views are opened under): `node scripts/check-standard.mjs wwwroot --url http://127.0.0.1:8080/ --views file.json`. A view with steps is measured after them, under its own name (`standard-<name>-...` pictures).
Each problem names one element on one page: its tag, id, the AtomicAUI class of the part, its own classes, its role in square brackets, its `aria-label` in braces, its own text, and in round brackets its path, a selector you can paste into the browser's search (`::shadow` in a path is the step into an open shadow root: search inside that host). Two elements are never one line or one count, on one page or on two. Then a Fix line and where it was seen: the sizes and themes of that page, each once:
```
AUI-02: Fill rgb(255, 0, 170) on div#hero.card (body > main:nth-child(2) > div:nth-child(1)) is no theme role. Nearest: --theme-error (rgb(231, 80, 76)). [C1]
    Fix: Take the nearest role: ...
    Seen in: page-desktop-light, page-narrow-light
```
Token problems come first, then the spacing rules of `check-layout` on the same views, apart, with fixes in class form on a page without React. The last line counts them apart: `check-conformance: summary {"views":4,"tokens":0,"layout":0}`; exit 0 means neither has a problem and every page was read in the state its view names: none still busy, no click missing ("When it is read", below). With `--tokens-only` the spacing rules are left out: `{"views":4,"tokens":0}`. `npm run verify` and `npm run verify:page` run the token part on the kit's own views, in their layout step (`npm run check:layout -- --tokens`): a token problem stops the page-only run as it stops the full one.
| Code | Problem | Fix |
|---|---|---|
| C0 | no element carries `data-aui-theme`, or the page carries a brand AtomicAUI does not have: nothing was compared | the attributes on `<html>` |
| C1, C2 | a colour that is no theme role (`--p-palette-*` is none), or is the same in light and dark | `var(--theme-<role>)` |
| C3, C4 | a font that is not Inter or JetBrains Mono; a size and line that is no type role (a line height left at `normal` is none, and is printed as `normal`) | `--typography-typeface-family`; `--typography-typescale-<role>-font-size` and `-line-height` |
| C5, C6 | a corner other than 0, 4, 8 or pill (a radius of exactly `50%`, the circle the library draws, is pill; no other percentage is); a shadow outside a popup, dialog, menu or tooltip, or one there that is no elevation of the library | a shape step; no shadow, or the `aui-elevation-<n>` class as it is |
| C7 | the page is not in the theme that was asked (`?theme=dark` in the address): that theme was not measured | `aui/aui-theme.js` in `<head>`, or start your theme state from the address |

How it decides, in every part alike (a button, tab or list item has no pass of its own):
| Value | Passes when |
|---|---|
| What a theme value is | what `references/standard/theme.json` holds: the theme roles, the default chart palette and the elevation shadows of every brand and theme, the type roles, the shape steps and the fonts, read once from the kit's own AtomicAUI build. No value is read from the page: a `--theme-*` variable, a type size, a radius or an elevation that the page's own CSS adds or changes is no theme value, in a stylesheet of its own or bundled into one file with the library |
| What is read | on each element that draws, wherever it sits (inside an inert or collapsed pane too) and whatever its size (one at `opacity: 0` is read), on its `::before` and `::after` (also one drawn only by its border or padding), on `<html>` and `<body>` (whatever their visibility: only `display: none` leaves them out; text loose in `<body>` too; their background whatever the size of their box and also when they are `visibility: hidden`, because it is drawn over the whole window), on what an open shadow root holds, and on HTML inside an SVG `<foreignObject>` (a slider, a colour field and an image button write no text: their fill and border only): text colour, fill, border, outline, gradient stops of the background, box shadow, text shadow, font, size and line, corners (both radii of each; a `calc()` corner is reported as written). A box with no width or height is read for what it draws outside itself: its outline, its shadow, text that nothing clips, and its `::before` and `::after` by their own size. On each SVG shape and SVG text: fill and stroke, nothing else |
| When it is read | once: when the page has loaded and its fonts are ready, with reduced motion asked of the page (`prefers-reduced-motion: reduce`, so a part that animates in is read and photographed finished), after the clicks its view names and before the tool presses or focuses anything of its own. Only what is on the page at that read is read; what a page draws later is not. A page that draws late marks its loading region `aria-busy="true"` until it has drawn: the check waits for it, up to 5 seconds. A page still busy after that does not get the ok line: `tokens not proved`, `"busy":N` in the summary, exit 1. Nor does a view whose click was not found (nothing on the page has that `aria-label`, `title` or whole text), because the page was not in the state the view names: `tokens not proved` with the view and the click, `"missedClicks":N` in the summary, exit 1, with `--tokens-only` too. A low "boxes read" number in the ok line is the sign of a page read too early. The check only reads: it never writes to the page |
| What is not read | an element that draws nothing: one that is `display: none` or inside one (what a closed `<details>` holds too), one below `<html>` and `<body>` that is `visibility: hidden`, one below them that is fully clipped away, with what it holds (`clip-path: inset(50%)` or another shape with no area: `inset(100%)`, a circle or ellipse with a radius of 0, a polygon whose points lie on one line; or `clip: rect(0, 0, 0, 0)` on an absolute or fixed box: the usual hidden form input; the ok line counts them, `Skipped: N elements`; a clip that leaves area is read), and an SVG shape with no box at all (inside `<defs>`, a clip path, a mask or a symbol); a zero-length SVG stroke drawn only by its round or square caps (it has no box either, and it does draw); what the page draws after the read; frames (`<iframe>`: run the check on the framed page's own address) and closed shadow roots; images, canvas, what an SVG `<use>` draws, scrollbars, other pseudo-elements (`::placeholder`, `::marker`, `::selection`); text in a `display: contents` element; gradients of a border image or a mask; drop-shadow filters; text decoration, text fill and text stroke colours; what the browser itself draws of a native control (a checkbox, a radio, a progress bar) and `accent-color`; and states the page was not in (hover, focus, an open menu). The ok line names what was read and lists these; it does not speak for them |
| Any colour above | clear, or its opaque form is a theme role: the role, or a state layer over it (`color-mix(in srgb, var(--theme-<role>) 8%, transparent)`). A mix of two roles is no role. A paint the check cannot read as a colour (an SVG `url(#gradient)`) is no role |
| The colour of a chart series | on a mark of a series in the library's chart (a shape of its plot, `.ts-chart__marks` inside `.aui-chart`, or a swatch of its legend, `.aui-chart-legend-swatch`), also one of the six colours of the library's default chart palette (`chart` in `theme.json`). The same colour on any other element is no role, and no other mix passes on a mark |
| Inset shadow (a ring, the stripe of a picked row), text shadow | its colour is a theme role as above, or a `--theme-shadow-*` role |
| Box shadow that is cast | the element floats, and the whole shadow equals one `aui-elevation-<n>` of the library in that theme |
| Theme | the element with `data-aui-theme` says the theme that was asked; a page that stays in light fails C7 and proves nothing of dark |

A gap to know: a native `<select>` keeps its line height at `normal` whatever the page sets, so it fails C4 (`Text 14 / normal on select ...`), and the check does not tell this case from a page that left the line height unset. By hand: write `appearance: none` on a drop-down select, then its line height follows the page; the options of a list select (`multiple`, or `size` above 1) stay at `normal` even so. There, or instead of both, use the select the library draws (`references/components/field.md`; the select recipe in `references/standard/recipes/field.md` on a page without React).

An address that does not answer is reported as that, with the address (`<address>: nothing answered (...)`, or `<address>: the server answered 404, not a page`), and nothing is measured. The other checks that open pages say the same in their own form, never with a stack trace: `check-standard` and `check-behaviour` as an AUI-12 problem of that page ("did not load"), `check:layout` as one line.

It proves values, not anatomy, not which role suits the job, not behaviour. A page with no AtomicAUI class passes if its own CSS uses only the library's variables. SKIPPED means no browser was found: nothing was proved.
