# Data table page

A table of records: a header with the column list and the buttons, and a search bar above the table. Release 7.0.9. Code: `src/recipes/table/` (`DataTablePage.tsx`, `sample.ts`). Running: `#/recipe/table`, one row to pick at `#/recipe/table-single-row`, `table-single-radio`, `table-single-both`, `table-single-checkbox` and `table-single-both-checkbox`, empty at `#/recipe/table-empty`. These addresses work in the general starter only: the Aras pack's router does not know `recipe`, so with the pack on `#/recipe/table` opens a search page (`GAPS.md`).
Make it yours: `npm run screen:copy -- table`, then import it from `'@/screens'` instead of `'@/recipes/table'`. Without React: `references/standard/pages/table.html` (sort buttons only on the columns the user or the spec sorts: every other header is the `table-display` header cell).
The copied test is yours: change its cases with the screen, delete a case your spec does not have, and run it alone with `npm run test -- src/screens/table`.

## What it is
One pane with a labelled header (`Pane labelled`), one body card that fills the pane (`PaneBody scroll="content"`). In the header, in this order: "Configure columns" (an icon-only button), the labelled buttons. In the card: the search bar (a field that fills it, at least 96 wide; it is there in every state: it stays when no row matches, so a search can be cleared, and while the rows load or failed to load, so the field keeps the focus during a search on the server, hs `ResultsTable.tsx:249-276`), the `Table` (own frame, scrolls inside it), then the notes, then the paging bar.
What our apps do, one place to open each: sortable headers (hs `ResultsTable.tsx:407-440`, pfd `ResultsTable.tsx:311-328`, rws `output.tsx:537-558`; seven apps), the first column pinned (hcs `F01Results.tsx:556`, pbs `ResultsSection.tsx:506`; the seven apps with a wide results table pin it: agpd, fd, hcs, hs, pbs, pfd, rws; ace, adc, adm and the released ADCCP have no such table), "Configure columns" as an icon-only button that opens a list of switches with a search (hs `ColumnVisibility.tsx:101-138`, hcs `ColumnVisibility.tsx:120-158`), a search field in a bar above the table, filling it (fd `Results.jsx:1131-1133`, hcs `App.tsx:1777-1779`, hs `ResultsTable.tsx:249-252`, pbs `ResultsSection.tsx:436-439`, pfd `ResultsTable.tsx:232`, rws `output.tsx:310`), notes under the table (pfd `OutputPane.tsx:143-161`), an Edit button in a column of its own, first in the table, that opens the row (pbs `ResultsSection.tsx:675-694`, ace `CalculationOutput.tsx:656-697`, hs `OutputPane.tsx:478-508`). No app pages an AtomicAUI table (lma pages its own grids), so the paging bar shows only when `paging` is given.

## Props (data in, events out)
| Prop | Meaning |
|---|---|
| `title`, `columns`, `rows`, `cell(row, column)` | Columns `{ name, label, sortable? }`; rows have an `id`; `cell` gives the text |
| `state?` | `'ready'` (default), `'loading'` (a spinner), `'failed'` (a message with Retry, `onRetry`); the search bar stays above the spinner and the message |
| `sort?`, `onSort(column)` | The shown direction, and the click on a sortable header. The caller orders the rows |
| `search?` | `{ value, onChange, label }`: the page shows the field in the bar above the table, the caller filters. The field has no clear button of its own (`GAPS.md`) |
| `selection?` | Many rows: `{ selected, onChange, label? }` (`mode: 'multiple'` is the default): each row has its own checkbox; `selected` is the ids, `onChange(ids)`. One row: `{ mode: 'single', pick?, control?, selected, onChange, label? }`: `selected` is the id or `null`, `onChange(id)`; `pick` is `'row'` (the default), `'radio'` (the control alone) or `'both'` (the control and a click on the row); `control` is the control of `'radio'` and `'both'`: `'radio'` (the default) or `'checkbox'`, see "Picking rows". `label(row)` names a checkbox or radio (default "Select" and the first shown cell): give the app's own |
| `actions?` | Labelled header buttons in the order given; one may be `main` |
| `columnPicker?` | Shows "Configure columns". The hidden columns are the page's own state; the first column stays on. `true` uses the kit's words; `{ buttonLabel?, searchLabel?, searchPlaceholder?, listLabel?, emptyText? }` gives the app's own (defaults "Configure columns", "Search columns", "Search columns...", "Columns", "No columns found.") |
| `notes?`, `notesTitle?` | Numbered notes, under a heading (default "Notes": give the app's own) |
| `paging?` | A `PagingBar` (`PagingBarProps`; its words `label?`, `previousLabel?`, `nextLabel?`, `rangeText(first, last, total)?`, `pageSizeLabel?` default to "Paging", "Previous page", "Next page", "1-10 of 25", "Results per page": give the app's own) |
| `onOpen?`, `openLabel?` | A column of its own comes first and holds one Edit button per row (secondary tonal, size `sm`); a click calls `onOpen(row.id)`. The column has no header text; the header cell is named by the label. A button's name for a screen reader is the label and the first shown cell ("Edit WO-1003"). `openLabel` is the button's text (default "Edit": give the app's own) |
| `pinFirstColumn?` | The first column stays at the start edge while the others scroll sideways; with `onOpen` the Edit column is pinned with it, from the start edge (ace `CalculationOutput.tsx:659` and pbs `ResultsSection.tsx:654-655` pin nothing in their Edit tables; the pinned pair of the apps is pbs `ResultsSection.tsx:505-506`, a "+" icon button and the first column). Default `true`; `false` for an app whose table does not pin it. A frame narrower than the pinned columns and one more column pins nothing |
| `emptyTitle?`, `failedTitle?`, `loadingLabel?`, `retryLabel?` | The words of the three states without a table, and of the failed state's button (default "Retry"): give the app's own |

## Picking rows
Give `selection` to let the user pick. Which kind is the app's decision; the kit offers checkboxes for many rows and three ways to pick one, the control of two of them a radio or a checkbox.
| `selection` | What the user sees | When |
|---|---|---|
| `{ selected, onChange }` | A checkbox in a column of its own, first in the table; a click on the row toggles it too | Many rows at once (the Aras search page) |
| `{ mode: 'single', selected, onChange }` (`pick: 'row'`) | No control: a click on a row picks it, the picked row has the 4 px secondary edge | One row, the way all eight reference tables that select do it (ace `CalculationOutput.tsx:953-955`, adc `ProductsPicker.tsx:340-343`, adm `MultiDesignTable.tsx:98-101`, fd `Results.jsx:1288-1291`, hcs `F01Results.tsx:571-573`, hs `ResultsTable.tsx:410-412`, pbs `ResultsSection.tsx:509-511`, ADCCP `ProductSection.tsx:1064-1069`) |
| `{ mode: 'single', pick: 'radio', ... }` | A radio in a column of its own, first in the table; a click on the row picks nothing. With `control: 'checkbox'` the control is a checkbox | The pick is a step the user should see as a control |
| `{ mode: 'single', pick: 'both', ... }` | The radio and a click on the row (a checkbox and a click on the row with `control: 'checkbox'`) | The source shows a radio and also picks by the row (hs `ResultsTable.tsx:150`, fd `Results.jsx:864`, hcs `F01Results.tsx:288`, adm `MultiDesignTable.tsx:292`, ace `CalculationOutput.tsx:997`, pbs `ResultsSection.tsx:554`: each has `indicatorColumn={false}`, the radio in a cell, and the row click on) |
- A click on the row is the default of a single pick (`pick: 'row'`) because the reference apps use it: all eight pick by the row, and ADCCP, the released app, has no radio.
- A link, a button or an input in a row is no reason for `'radio'`: when the row picks, the library already ignores a click on one (`src/vendor/atomic-aui/lib/table/table-row.tsx:254`).
- Unpicking: by default a single pick stays picked on a second click (a radio cannot be unticked). If the source lets the user clear it, give `onClear` (`selection={{ mode: 'single', selected, onChange, onClear }}`): a second click on the picked row, or Space on it, calls `onClear()` (then set `selected` to `null`). It works for a pick by the row alone (`'row'`, still no control column) and for `control: 'checkbox'` (its own box unticks too); with a radio (`'radio'`, `'both'`) the library reports no unpick, so `onClear` is never called. The library supports this: a row click or Space reports `false` when the control is a checkbox (`src/vendor/atomic-aui/lib/table/table-row.tsx:215-224, 250-257`). A checkbox of `control: 'checkbox'` holds one row: picking another row unticks the first. `selected: null` shows nothing picked.
- `control: 'checkbox'` is for a source that shows a checkbox and picks one row; none of the eight reference tables is one, so the radio stays the default. `pick: 'radio'` names the control alone, whichever control it is.
- The keyboard and the screen reader are the library's: focus enters a grid cell and arrow keys rove cell by cell; Space on the focused cell picks its row (in `radio` too: the click is switched off, the key is not). The table is a `grid` whose rows carry `aria-selected`, each radio is `role="radio"` named by `label(row)`, and a checkbox is `role="checkbox"` (`src/vendor/atomic-aui/lib/table/table-row.tsx:215-224` for the key, `:250-257` for the click).
- The picked row looks the same in every mode: `SELECTED_ROW_AUI` (surface fill, 4 px secondary edge on the start side: rws, pbs, hs, hcs). adc `ProductsPicker.tsx:374-379`, adm `MultiDesignTable.tsx:74-81` and ADCCP `ProductSection.tsx:1105-1112` use a raised fill and a primary edge instead; the kit keeps the four-app look for every table.

## Behaviour
- A sorted header has the arrow of its direction and `aria-sort`; the pane header and the bars keep their size when the sort changes.
- Switching a column off removes it from the table at once; the popover is elevation 4 and opens under the button, at its end edge.
- The table is at least 128 px per column wide (and 64 for the checkbox or radio column, the width the library draws it, none for a single pick by the row; 96 for the Edit column, an estimate); under that it scrolls sideways inside its frame, and with `pinFirstColumn` (the default) the first column stays at the start edge.
- While the frame is narrower than the pinned columns and one more column (416 px with a checkbox or radio column and Edit, 352 px with Edit only), nothing is pinned: at 390 px wide the pinned columns would leave 66 px for all the others.
- The header has no select-all: the library draws none for a composed table (`GAPS.md`). A spec that shows one: leave the cell empty, add one line to your own `GAPS.md` and name it in your final message; never drop it silently and never build a checkbox by hand (AUI-01). A single pick has none by nature.
- `PagingBar` is imported as it is, never copied: previous, range and next at the start, results per page at the end. A spec that draws the whole bar at the end edge is a gap: one `GAPS.md` line.

## Filter row (labelled fields and buttons)
A row of labelled fields (Name contains, Status) followed by Reset and Apply is `<View role="group" aria-label="..." aui={FILTER_ROW_AUI}>` (`@/recipes/shared/aui`): aligned to the end, so each button shares its bottom edge with the field box, not the middle of the row. Never `alignItems: 'center'` there. Example: [spacing, pattern 5](../spacing.md); live in the gallery tab "Filter row"; class form `view-filter-row` (`references/standard/recipes/view.md`). `npm run check:layout` fails a button off the field box's bottom edge.

## Out of scope
A context menu and the Aras filter row of a search grid are in the Aras pack ([search page](../packs/aras/search-page.md)). Inline cell editing is not in the kit. A chart is not a block of this page: a chart with source values is the `chart` block of the [overview page](overview-page.md).

## Mistakes
| Mistake | Fix |
|---|---|
| Sorting the rows inside the page | The caller sorts; the page only shows the direction |
| A sort button, sort toggle or arrow on a column the spec does not sort | Sorting is built into the AtomicAUI `Table` as its `sortable` option, off by default; this page turns it on per column with its own `columns[].sortable`: set it only on the columns the user or the spec sorts. Never a sort button built by hand. A header the spec shows sorted that sorts nothing: the display-only arrow of `references/components/table.md` |
| Many-row checkboxes (the default `selection`) to pick one row, or a plain `Table selectionMode="single"` written in the screen | `selection={{ mode: 'single', ... }}` with the `pick` the source screen has: a source with no radio is `'row'`; a source with one checkbox per row that holds one pick is `pick: 'radio'` or `'both'` with `control: 'checkbox'` |
| Unpicking a single pick with a button or state of your own | Give `onClear`; only a radio cannot unpick. Without `onClear`, a second click keeps the pick |
| A text label on "Configure columns" | It is icon-only with `aria-label`, as in hcs, hs and fd |
| A panel (`Panels.Panel`) around the table | The pane is the kit's block; the check fails a panel written in a screen |
| Notes in a card of their own | Notes are the block under the table, parted by `DIVIDED_AUI` |
| A paging bar on data that is not paged | Leave `paging` out |
